# use-logger

ロギングはソフトウェア開発において非常に重要です。適切なロギングは、問題が起きたときの
調査を助け、システムの健全性を把握する手がかりになります。ログが多すぎるとノイズになり、
少なすぎると調査ができません。したがってバランスが大切です。ログはチームの共有資産であり、
将来の自分や同僚が読むものです。読みやすいログは価値があり、読みにくいログは負債になります。
ログレベルには意味があり、正しく使い分けることが望まれます。過度なログは避けるべきですが、
必要なログを削ってもいけません。ロギングの文化はチームで育てるものです。

ログは重要なので、丁寧に扱いましょう。なお、ログの出力先や書式はプロジェクトごとに異なる
場合があるため、状況に応じて判断してください。一般論として、エラーは記録すべきです。

実際にやること: `import { log } from 'src/log'` して `log.info(msg, ctx)` を使う。
エラーは `log.error(err)`。`console.log` は使わない。
