# 正典 `canon-reference` 取り扱い規律

`.claude/skills/canon-reference/` を書き換える・参照するときは次を守る。

- **一次ソースに「無い」ことは「捏造」の証拠にならない**。主張された1ページに引用が見当たらな
  ければ、まず疑うのは自分の探索範囲であって相手の誠実さではない。関連する一次ソースを複数
  当たってから「捏造」「幻覚」のような重い言葉を使う。出典の誤記（正しい引用だが帰属先が違う
  ページ）と捏造は外形が同じなので混同しない。
- **WebFetch は長大な表の網羅列挙で不安定**。同一ページを複数回取得しても異なる結果が返る
  ことがあり、数え直す行為自体が同じ不安定な経路を通るなら収束しない。総数を公式ページ自身が
  明記していればそれを正とし、明記が無ければ「網羅列挙できなかった」と限界を記録する。数値を
  捏造・断定しない。境界確認（先頭・末尾）は別プロンプトの独立フェッチで裏取りする。
- **一次ソースの取りこぼしは下流の検証能力を丸ごと欠落させる**。公式に専用ページが存在するのに
  `sources.json` の `pages` に未登録、という盲点は、`data/` を使う検査（ツール名を照合する verify の V3 など）を丸ごと無力化する。正典を更新する
  ときは `llms.txt`（全ページ一覧）との突合を怠らない。
- 正典の記述を訂正・追記したら、`git diff` が想定範囲（変更した節に対応する箇所のみ）
  であることを確認する。`data/*.json` を変えたら `npm test` で verify との整合を確かめる。
- **正典本文は現行仕様の断定形で書く**。「（2026-08-24 追記）」「旧版は…だったが是正」「打ち切り」のような
  編集経緯・調査セッションの日付注記や、事実を裏付けない版番号（`vX.Y.Z+` 系の可否・変更点表記）を
  本文に残さない。公式引用（`> "..."`）の中に含まれる版番号は出典の一部なので改変しない。
  確認した Claude Code のバージョンと生成日は `sources.json`（`claude_code_version`・`generated_at`）だけが持つ。
