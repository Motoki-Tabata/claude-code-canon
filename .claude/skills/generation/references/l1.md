# L1: CLAUDE.md と Rules

正典: `docs/L1_CONTEXT_MANAGEMENT.md`。L1 は「毎セッション必ず要る」静的な知識と規約を置く層である。

## CLAUDE.md

- **200行以下**。超えると重要なルールが埋もれ、遵守率が下がる。手順やテンプレートは L2 の Skill に切り出す。
- frontmatter は付けない（CLAUDE.md は frontmatter をサポートしない）。
- `@import` で構造化できる（相対パスはインポート元が基準。`@~/…` も可。最大4段）。
- **書くもの**: Claude が推測できないコマンド・標準と違うコードスタイル・テストの実行方法・リポジトリの作法・固有の設計判断・環境の癖・非自明な罠。
- **書かないもの**: コードを読めば分かること・標準的な慣習・API ドキュメントの写し・頻繁に変わる情報・長いチュートリアル。
- **削除テスト**: 各行について、「これを消したら Claude が間違えるか」を問う。間違えないなら消す。
- `<!-- -->` のコメントは、読み込み時に取り除かれる。作者向けのメモを書く場所ではない（[no-leaks.md](no-leaks.md)）。

## Rules

- 置き場は `.claude/rules/<topic>.md`。ファイル名は内容を表すトピック名にする。
- `paths:` の frontmatter（YAML のリスト）で glob を指定すると、該当するファイルを読むときだけ読み込まれる。`paths:` が無い rule は、CLAUDE.md と同じく無条件に読み込まれる。適用範囲が限られる規律は `paths:` を付けて、常時の文脈を太らせない。
- glob の例: `src/**/*.{ts,tsx}`・`lib/**/*.ts`・`*.md`。
- 1ファイル1機能。10ファイルを超えたら統合を考える。

## Auto Memory（要件にあるときだけ）

Claude 自身の学習を引き継ぎたい要件があるときは、`MEMORY.md`（索引。200行または25KB まで）と topic ファイルの構成で書く。
