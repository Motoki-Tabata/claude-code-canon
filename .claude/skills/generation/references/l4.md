# L4: Hooks と MCP

正典: `docs/L4_AUTOMATION.md`。この層は、要件と constraints が許すときだけ作る（`hooks`・`mcp` が `allowed: false` なら、生成物のどこにも現れてはならない。verify の V9 が止める）。

## Hooks

配線は `.claude/settings.json` の `hooks` に、ハンドラの実体は `.claude/hooks/**` に書く（正典の公式例が、実体を `${CLAUDE_PROJECT_DIR}/.claude/hooks/` に置く）。片方だけを作ると、配線だけが配置されて参照先が無い壊れた構成になる。

- **ハンドラの種類**（`type`）: `command`（シェル実行）・`http`・`mcp_tool`・`prompt`・`agent`。共通のキーは `if`（permission rule の構文。ツール系のイベントだけ）・`timeout`（秒）・`statusMessage`。
- **`command` の書き方は2通りで、混ぜない**。
  - shell 形式: `"command": "node \"${CLAUDE_PROJECT_DIR}/.claude/hooks/x.js\""`（`args` を書かない）。
  - exec 形式: `"command": "node", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/x.js"]`（実行ファイルと引数を分ける）。
  - `"args": []` は「引数なし」でなく「exec 形式にする」の意味になる。そこに引用符や空白を含むコマンド行を書くと、全体が1つの実行ファイル名として起動に失敗し、hook は**黙って落ちる**（PreToolUse ならツールがそのまま通る）。
- **終了コード**: 0＝成功（stdout を JSON として読む）／2＝ブロック（stderr が Claude にフィードバックされる。効果はイベントによる）／その他＝ブロックしないエラー（stderr は記録に出るだけ）。確実に止めたいなら 2。
- stdout に、JSON に見えて妥当でない文字列を出さない（hook のエラーになる）。
- パスは `${CLAUDE_PROJECT_DIR}`（プロジェクトのルート）を使う。絶対パスを書かない。
- イベント名は正典の全イベント（33種）に実在するものだけ。
- スクリプトには実行権限が要る。配置後の手作業として、design-map の「配置時の追加手順」に載っていることを確かめる。

## MCP（`.mcp.json`）

```json
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}
```

- **資格情報は必ず `${VAR}` の展開で書く**。キーや token を直書きしない（verify の V4 が止める）。展開できるのは `command`・`args`・`env`・`url`・`headers`。`${VAR:-既定値}` で既定値を置ける。未設定で既定値も無い `${VAR}` は、そのまま未展開の文字列として使われて接続に失敗する（パースエラーでなく、変な値での接続になる）。
- transport は `http`（推奨）・`stdio`・`sse`（廃止の方向）・`ws`。
- ツール名は `mcp__<server>__<tool>` の形。
- OAuth や環境変数のセットアップが要るときは、配置後の手作業として design-map の「配置時の追加手順」に載っていることを確かめる。

## Experimental

Agent Teams・Channels・Monitors・Themes に依存する場合は、それが実験機能であることを本文で明示する（verify の V4）。constraints の `experimental` が `allowed: false` なら、そもそも作らない。
