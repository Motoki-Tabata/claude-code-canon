# change-plan.md（小の G1／大の G2 の対象）

変えるファイルと指示の記録。小の経路は `/canon-plan` のメインが、大の経路は `/canon-design` のメインが書く。builder が読むのはこのファイルの自分の担当のファイルの指示だけなので、1件ごとに独立して読める形にする。サイズの上限は `npm run check` が数える（ファイル1件の指示 2.5KB・参照元の扱い1件 300バイト・全体は小 48KB／大 64KB）。

## テンプレート

````markdown
## ファイル
- path: <対象ルート相対のパス>
  op: modify|new|delete
  reqs: [R1, R2]
  instruct: <何を・なぜ。modify は直す箇所（節・行）と直し方、new は置く内容の要点、delete は消す理由>

## 影響の語
- `<変える語・コマンド・設定キー>`

## 参照元の扱い
- <path>:<line>:<term>: 変える
- <path>:<line>:<term>: 変えない（<理由>）
- <path>: 変えない（<理由>。件数が多い語はファイル単位で答える>

## 検証コマンド
- `<worktree で実行する対象の検証コマンド>`

## 機能と責務
（大の経路だけ。8KB まで）

## モデル割当
（大の経路だけ。3KB まで）
````

## 書き方

- `## ファイル` の各件は `path`・`op`・`reqs`・`instruct` が必須。`reqs` は requirements.md の確定要件の ID で、確定要件がどれかのファイルの `reqs` に現れなければ `check` が NG にする。`path` は重複させない。
- **`instruct` に新しい本文を丸ごと書かない**。新しい本文は builder が書く。計画には「何を・なぜ」だけを書く。上限を超えるのは、たいてい前の段の再掲か、新しい本文の丸写しである。
- 内容を変えないファイルは `## ファイル` に載せない。
- **`## 影響の語`**: 要件の want が変えるコマンド名・既定の挙動・設定キー・Skill 名・語を、バッククォートの箇条書きで挙げる。これを `npm run impact -- --root <worktree> --out work/<ts> --files <ファイル,…> --terms <語,…>` の `--files`・`--terms` に渡す。変えるファイルの一覧と同じ集合でなければ、`check` が NG にする（古い `impact` を通さない）。
- **`## 参照元の扱い`**: `impact.json` の該当（触らないファイルが、変えるファイルか語に触れている箇所）のすべてに答える。該当ごとの ID は `<path>:<line>:<term>`。答えは「変える」か「変えない（理由）」で、「変える」と答えたら、そのファイルを `## ファイル` にも載せる。「変えない」には理由が要る。同じファイルの該当が多いときは `<path>: 変える|変えない（理由）` と、ファイル単位で答えてよい（そのファイルの全該当を覆う）。1件1行・300バイト以内。触らないファイルが変えた語を参照している食い違いを、生成のあとでなく計画の段階で表に出すための答えである。
- `## 検証コマンド`: worktree で実行する、対象のテスト・ビルド・lint のコマンド。メインが実行する。worktree には追跡中のファイルしか無い（`node_modules`・`.venv`・ビルド出力・`.env` は入っていない）ので、依存の導入コマンド（profile の `package_manager` に応じたもの）を先頭に含める。導入できない対象と、テストが無い対象は、その旨と代わりの確認方法を書く。
- 大の経路の `## 機能と責務`・`## モデル割当` の書き方は design Skill の references を読む。小の経路は書かない。
- 小の経路の条件（`check` が機械で見る）: 対象に既存のカスタマイズが1件以上ある・`inventory` で0件の機能のファイルを新設しない・Skill／Subagent／Plugin を新設も廃止もしない。1つでも欠ければ大の経路にする。
- 承認状態は書かない。
